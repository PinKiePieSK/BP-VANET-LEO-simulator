# OSM RSU report cez explicitný LEO uzol a dvojkoncovú geometriu

**Stav:** overená izolovaná paketová sonda, 22. 10. 2026 UTC. **Presný príkaz:**

```bash
cd '/home/ubuntu/Documents/ChatGPT/Bakalarska praca'
bash tools/run_osm_leo_hop_probe.sh
```

**Hypotéza.** Rovnakých päť 96 B reportov `ICB1` z [OSM→CAM→RSU behu](osm-ba-cam-rsu.md) možno preniesť v jednej časovej osi ns-3 cez *explicitné uzly* RSU → pevný UT → LEO objekt → gateway proxy → server, ak je z archívnej geometrie pri každom odoslaní známa a nad experimentálnou maskou aj vzdialenosť UT–LEO, aj LEO–gateway pre **to isté katalógové ID**. Ak brána chýba alebo má zápornú eleváciu, scenár sa musí uzavrieť bez odoslania. Toto je skúška otvoreného geometrického paketového modelu, nie simulácia Globalstar RM200M ani predpoveď služby.

## Vstupy a presný mechanizmus

`data/fixtures/osm-ba-five-icb1-reports.csv` má päť presných reportov skopírovaných z `RSU_REPORT_TX` overeného `results/osm_ba_cam_rsu/positive.csv` (pôvodný SHA-256 `c219a719a883c56af12fd098ddd7ea65ef01e0cf95948d73a1c2d9303b84031b`; verzovaná fixture `e0cd0f8260050a1bf97804c7c67623b5cd59697523921398a563c9b124449f07`). Pripravený [OSM geometrický výpočet](osm-cam-three-group-geometry.md) má pri pevnej RSU WGS84 `48,1482681° N; 17,1085885° E; 0 m` a hypotetickom **centre mesta Nemea** `37,8167° N; 22,6667° E; 0 m` v UTC 12:45:05 až 12:45:09 päť vzoriek archívnej Globalstar GP/OMM skupiny. Uvádza spoločného kandidáta **NORAD 37741**; jeho kanonický OMM record SHA-256 je `64a1f3de50a39556c1d94d33d7369589ee0b6ea3a3624af70c80796c661311aa`. Príprava znovu kontroluje hash CSV `f7c2a1280c4f1a005971cc9ab5ab2c20e053422b4083dca3c0a84fd09edc59c3`, metadáta, manifest snímky, gzip aj surové OMM bajty a fixture. Snímka ReTLEctor/CelesTrak bola stiahnutá **12:49:43,719531 UTC**, teda až *po* prehrávanom úseku. Ide o retrospektívnu rekonštrukciu, ktorú by terminál o 12:45 nemohol takto poznať.

`tools/prepare_osm_leo_hop_probe.py` vyžaduje výslovné `--gateway-proxy nemea-city-proxy`; bez neho skončí pred vytvorením plánu. Pre každú vzorku ukladá UTC, ID a hash vybraného OMM záznamu, eleváciu (°), šikmú vzdialenosť (km), `round(range_km/299792.458 × 10^9)` jednosmerných ns na oboch hranách, ID udalosti a všetkých 96 B v hex. **10° je naša experimentálna maska, nie publikovaná maska RM200M.** Pri chýbajúcom spoločnom ID alebo rozsahu sa plán nevytvorí; pri známom ID pod maskou má riadok `enabled=0`. Skutočné súradnice antény, priradenie gateway/beam-u ani jej prevádzkový stav nepoznáme. Výpočet používa archívne OMM, SGP4 a validovanú Astropy transformáciu z predošlého míľnika; C++ polohu nepropaguje nanovo.

`src/osm-leo-hop-probe.cc` vytvorí päť ns-3.48 uzlov `RSU`, `UT`, `LEO proxy 37741`, `gateway proxy`, `server` a štyri point-to-point linky. **Všetky štyri sú idealizované 1 Gb/s P2P;** LAN a gateway→server majú 0 ns modelovú propagáciu, UT→LEO a LEO→gateway majú pred každým z piatich vyslaní vlastné `r/c` podľa vzorky. IPv4 sa smeruje cez tri prostredné uzly, UDP port servera je 45000 a kontrolné súčty IP/UDP sú zapnuté. Satelit má **samostatný paketový uzol**, ale *nemá orbital mobility model v ns-3*: objekt 37741 označuje archívne vybranú geometriu a aktualizované kanálové oneskorenie. Brána sa vyhodnotí **raz pred TX** reportu, nie počas letu; vzorky sú od seba 1 s, takže krátky let sa v tomto teste stihne pred ďalšou zmenou. Neznáme prechody medzi vzorkami, Doppler, RF prijímací výkon, kolízie, PHY/MAC, plánovanie, registrácia, servisný front, opakovanie, beam a handover nie sú zachytené. 1 Gb/s **nie je priepustnosť Globalstar**. IP/UDP na satelitných P2P hranách je diagnostická výskumná enkapsulácia, **nie RM200M natívny správový protokol**.

`trace.csv` má pre každé ID `RSU_TX` a `SERVER_RX` so skutočnými 96 aplikačnými bajtmi a na každej zo štyroch hrán `PHY_TX/PHY_RX` s presnými **126 B ns-3 PPP+IPv4+UDP rámcami**. Polia `time_us` sú mikrosekundy od UTC 12:45:00, `layer` odlišuje `icb1-app`, `ns3-p2p-ppp-ipv4-udp` a `geometry-only`, `detail` zaznamená vybraný objekt, dva delays alebo dôvod `GEOMETRY_BLOCK`. PPP rámce nie sú satelitné RF rámce. Kontrolný Python checker overí všetky ID, report magic/verziu, čas RSU, SHA-256 pôvodnej 41 B CAM, payload a IPv4/UDP checksum na každom hop-e, štyri TX/RX dvojice, ich poradie a čas `r/c + 126×8/1 Gbit/s` s toleranciou 2 µs kvôli mikrosekundovému trace. Server v C++ pri príjme kontroluje dĺžku/magic; hĺbkový audit vykoná checker a jeho úspech je povinnou súčasťou runnera.

## Význam pre ďalší simulátor

Toto je **dôkaz paketového priechodu cez samostatný LEO uzol a dve geograficky zladené vetvy** nad rovnakou OSM RSU udalosťou. Neznamená, že GP objekt je práve obsluhujúci alebo aktívny, ani že by používateľský terminál a brána boli kompatibilné s 96 B UDP reportom. [Globalstar opisuje bent-pipe architektúru](https://www.globalstar.com/en-us/about/our-technology), ale [RM200M publikovaný profil](https://www.globalstar.com/getmedia/932da082-c545-4ed1-b7fc-67ff34967651/rm200m-sales-sheet.pdf) je natívna MO/MT správa, nie tento IP link. Do spoločného porovnania treba pridať konkrétny certifikovaný terminál/API, skutočný gateway/beam, model user/feeder RF alebo meraniami kalibrovaný servisný obal, rýchlosť/fronty/opakovania, a nezávislú validáciu na tej istej službe. Bez toho je číselné oneskorenie iba vlastnosť nášho otvoreného P2P modelu.
